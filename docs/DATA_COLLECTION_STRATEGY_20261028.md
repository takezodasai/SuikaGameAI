# 学習に役立つデータを計算時間当たりで増やす収集戦略

2026-10-28。関連研究・AI全体の設計は [HIGH_SCORE_AI_RESEARCH_20261028.md](HIGH_SCORE_AI_RESEARCH_20261028.md)。この資料の配分・設定は次の実験案であり、現在の収集設定は変更していない。

## 1. 結論

**自然GOの軌跡は軽量MCTSを中心に集め、方策教師が必要な盤面だけ追加探索する、という分業を推奨する。** ただし過去盤面の完全復元は未達なので、再評価結果はまず予測上の教師として区別する。復元からの長期returnをそのまま元の実ゲームの正解へ上書きしてはいけない。

全手を8192〜32768回・深さ8〜16にする収集は、現時点では勧めない。計算時間の大半がランダムrolloutになる条件があり、自然GO・独立seed数が極端に減る。中規模・大規模が強いと断定する同seed実験も不足している。

当面は現Player・固定5候補・同期・深さ4の128/256回、少量の深さ6／256回を保持。512回以上は教師の再評価に役立つかを少数盤面で先に確認する。学習効率の最終判定は一致率だけでなく、**累積CPU時間を合わせて学習したagentの未使用seedでの自然GO得点**とする。

## 4. 深く考えたデータほど良いのか

深さ4／128では4手目のactionの約99.99%がrollout。深さ6／256では5〜6手目は全部rollout。深さ12／8192でも7〜12手目は全部rollout、6手目以降のaction再訪はゼロ。深くすることでランダム方策の長い結果は調べられるが、長期の各行動が木で比較されているわけではない。

一方8192／深さ4の1ゲームでは4手目の木action比率71.06%、再訪615,280回があり、大予算が木の成長に無意味という結論でもない。問題は、その費用が実ゲーム得点・教師の再現性・学習の改善へ変換されたかである。

root訪問分布の平均正規化entropyは128回0.926、256回0.897、512回0.867。最大訪問候補の平均占有率は30.8%、33.3%、36.3%。低予算教師は分布が平らになりやすい。これだけで誤りとは言えず、**探索seedを変えた教師同士の一致率**と、モデルの模倣率を比較する必要がある。

## 5. 教師信号別に収集目的を分ける

|教師|実際に表すもの|よい収集方法|してはいけない扱い|
|---|---|---|---|
|MCTS選択位置|その設定・探索seedの決定|少数重要盤面の複数seed／大予算再評価|全行動が最適というラベル|
|訪問分布|UCTと探索予算に依存する統計|実反復・訪問・候補集合・終了理由を保存|真の最適方策確率と同一視|
|MCTS評価値|有限深さ・rolloutの予測return|物理・時刻・chance条件を付記|自然GOの実追加得点と混ぜる|
|実MC return|収集方策下での自然GOまでの実追加点|多様な完了軌跡・方策ID・終端理由|未選択行動にも同じ値を付ける|
|同状態の行動比較|条件を統一した行動間の差|複数行動×複数future、観測範囲限定policy|1つの未来の幸運を真の優劣とする|
|将来イベント|観測できた方策下の到達|callback＋tick＋action ID、unknown mask|旧ログ未観測を失敗とする|

価値の初期MC学習では、すべてを強いAIでプレイする必要はない。収集方策の価値を学ぶことを明示し、方策混合による校正を確認する。ただし「最適価値」や新しい強い方策の価値を保証するものではない。

方策学習では多様性に加え、同一盤面の教師の安定性と改善余地が必要。高得点ゲームの全行動を重くする方式は既に一貫した改善がなかったため、その繰返しより**行動の比較情報**を増やす。低品質教師を捨てず、重み・behavior・実反復を分離する。

## 6. 段階的収集と計算配分

最適比率は未知。以下は次のパイロットに使う**計算時間の配分案**で、投入ゲームの確率ではない。

|用途|初期の時間配分|目的と条件|
|---|---:|---|
|軽量の自然GO、深さ4・128/256|60%|独立seed、実return、通常・失敗局面|
|中規模／深さの診断|20%|主に深さ6・256、少数深さ4・1024。強さ未検証の大予算へ全振りしない|
|通常＋重要状態の再評価|15%|復元・時刻監査を通過後。teacher stability／中間xの比較|
|スイカ生成後continuation|5%|復元監査を通過後。自然開始の分布と別管理|

再評価・continuationがまだ安全でなければ、その20%は停止しておくか軽量収集へ回す。実装済みであるかのように収集コマンドへ入れない。8192〜32768回の自然GOを日常的に増やす時間枠は現段階では0%。同じ計算時間で教師・実ゲームの改善が示されたら再配分する。

再評価盤面は、例えば40%無作為、30%モデル／MCTSの不一致・探索seed不安定、15%WM等の前後、15%GO近傍を候補とする。これは最適閾値ではなく偏りを監査できる初期設計。元ゲーム・選択確率・抽出理由を保存し、無作為枠で自然分布評価を残す。優先抽出はPER [R27] の考え方に近いが、TD誤差の大きさが物理予測の誤りである可能性もある。誤差が大きい全状態へ無制限にCPUを配らない。

## 7. 復元・再評価で必要なこと

既存PathSessionで、同じcold rootから各経路を独立に再生することは可能。branch途中の位置・速度だけをコピーして接触キャッシュを保持したと言ってはいけない。

1. 元の判断開始状態と、復元後の0tick状態を照合する。
2. 無操作・同一操作で25/50/100tick等を比較し、最初に点・合体・GOが分岐するtickを特定する。
3. 同一root内の繰返し再現性と、元の実ゲームとの一致を別に監査する。
4. 接触・合体・GO近傍は特に独立した評価群にする。
5. seedから実ゲーム全prefixを再生する案も、通信間tick・乱数状態が必要で、seedだけで完全復元できるとはしない。

高探索で再評価して得られるのは、そのシミュレーターの推定値。自然GOまでの実returnを得るには各候補を実際の継続環境でプレイする必要があり、短い再探索と同じ費用ではない。まず短期のbranch結果＋将来価値推定を診断し、少数だけ長い継続を実行する。

同じfutureサンプルを行動間で使えば差の分散が下がる可能性があるが、方策へ隠れた系列を渡さない。公開タイミングでNEXTを1つずつ開示する。未来に応じて行動を変えるべき段階では正しく適応させる。期待値比較で都合のよいchance結果だけを選別しない。

## 9. 計算時間の方式

|方式|収集での位置付け|
|---|---|
|固定反復|教師比較が容易。遅い局面の時間が伸びる|
|固定時間|wall予算は明確だが実反復・方策が負荷で変化。各手で同じ情報量にはならない|
|固定反復＋時間cap|現収集の推奨。十分早ければ指定反復で終了し、遅い局面を制限|
|adaptive／importance|節約の余地はあるが早期終了と候補追加が相互作用。新しい教師方策として識別し、現段階の比較には混ぜない|
|GO危険度で時間を増加|本当に候補の優劣が不確かなら有用かもしれない。系統的GO誤差の盤面では増やしても無駄|

現収集の固定反復方式は安定判定OFF、auto depth OFF、widening OFF。120秒／240秒を使い切る目的ではない。通信720秒はplan_stepの状態取得・同期探索・移動・落下・post25の応答待ちであり、起動/reset/metadata取得等へ一律適用されない。反復境界と終了集計により思考capは超過し得るため、実時間とtime_overrunを保存する。

### 次回の混合収集コマンド（今回実行していない）

既存収集が終了してから、新しい出力・空いたポートで開始する。10時間は新規投入の期限で、drainは実行中ゲームが自然GO等で保存されるまで延長する。強制的に10時間で切らず、完了した軌跡を優先する。Ctrl+C時は安全な手の境界まで待つ。

```powershell

$tag = (Get-Date -Format "yyyyMMdd_HHmmss") + "_" + [guid]::NewGuid().ToString("N").Substring(0,8)
$out = "outputs\research_collect_$tag"
$profiles = "outputs\research_profiles_$tag.json"
$gameSeed = Get-Random -Minimum 10000000 -Maximum 2000000000

@'
[
  {"depth":4,"iterations":128,"weight":0.70},
  {"depth":4,"iterations":256,"weight":0.20},
  {"depth":6,"iterations":256,"weight":0.10}
]
'@ | Set-Content -LiteralPath $profiles -Encoding UTF8

Write-Host "保存先: $out"
.\.venv\Scripts\python.exe .\collect_overnight_mcts.py `
    --exe ..\Unity\Builds\SyncOptimized_03\SuikaGameAI.exe `
    --output $out --workers 2 --hours 10 --shutdown drain `
    --think-seconds 30 --communication-timeout 720 `
    --profiles $profiles --game-seed $gameSeed --schedule-seed 20261028 `
    --max-jobs 1000 --max-steps 100000 --base-port 41800
```

A/B/B2/C単独はprofilesの配列を1要素・weight1へ替える。Cだけcap60へ変更する。単にCLIのmax反復を変えて現行収集中ジョブを変更しない。現Playerは旧イベント記録なのでメロン共存の瞬間まで完全に保存できる構成ではない。LearningEvents_02等の新記録Playerは次の短時間互換テスト後のセッションで使う。

再開は既存の出力へ `collect_overnight_mcts.py --output 対象フォルダ --resume`。保存済み設定を使うため、別プロファイルへ変更する操作ではない。Ctrl+C後の途中ゲームの過去部分は残るが、ゲーム途中からnative物理状態を厳密に再開する機能ではない。新attemptの重複・完了記録は収集側の規則に従い管理する。

|再現時刻|tickやaction IDは一部ログに存在|操作要求／探索開始／落下／観測終了のclock、cooldown、rng stateの非公開保管|
|初期系列・split|seed/初期8系列で既にgroup化|reanalysis枝・continuation・左右反転等も元groupを継承してTest漏洩を防ぐ|

巨大な全traceを常時保存するより、通常はcompact＋raw state、重要盤面だけfull traceに分ける。I/Oを削る場合も教師の元盤面・候補・時刻は削除しない。

## 12. 本当に効率が上がったかの試験

1. 同じ累積worker-hourで軽量・混合・高探索のデータ予算を揃える。学習更新数・モデル・splitも固定する。
2. 方策では教師自身の別seed一致率、訪問分布KL、実行時の得点を区別する。高探索の推定Qを真値にしない。
3. 価値ではMC誤差に加え、同状態行動順位とGO直前校正を測る。イベント未知を分母から外す。
4. 新しく収集した未使用seedの自然GOを対応比較する。Testを繰返しhyperparameter選択に使わない。
5. 学習効率は「最終得点差／収集＋再評価＋学習の計算時間」、doubleは達成率と区間で別報告。単純にゲーム数が多い／entropyが低いから勝ちとはしない。

最初の具体的開発は、主レポートの**時刻監査付き同状態行動比較基盤**。これにより、強い教師を作る追加探索が有益か、価値モデルが行動差を読めるか、中間xに価値があるか、を同じ小規模資料で判断できる。
