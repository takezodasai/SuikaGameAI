# 動的ルート候補MCTSと基準MCTSの自然GO比較

2026-10-31。出力：`Python/outputs/watermelon_dynamic_01`。

## 結論

動的候補MCTSを独立モードとして実装し、Watermelon Labで対応する自然GO比較まで実行した。**実装と比較は完了したが、性能改善は確認できなかった。標準採用しない。**

実行できた6ペア・12ゲームは全て自然GO。追加得点は基準平均777.83点、改良703.67点、平均対応差−74.17点。改良3勝3敗で、盤面ごとの方向も異なる。新規スイカ・2個共存・ダブルは両方式とも0/6だった。今回の結果から、ダブル到達率を改善したとはいえない。

独立した元盤面は3つのみで、2つの未来系列による繰り返しを6つの独立した元ゲームとは扱わない。この近似環境での結果であり、通常ゲーム開始からの性能を証明する比較ではない。

## 実装した探索方法

元の`MctsPlanner.cs`を編集せず、`RootRefinedMctsPlanner`へ実験用の処理を分離した。既存のNode・Edge・Report型を利用し、探索本体のコピーに候補追加の差分だけを加えた。コピー元のハッシュをヘッダーへ残し、Pythonテストで宣言した差分を取り除くと元本体に一致することを検査している。

1. 最初の32回は `[0,.25,.5,.75,1]` の固定5候補。
2. 32回完了時、ルートの各候補について `visits >= 4`、落下成功、即時予測非GOを満たすものを選ぶ。
3. 平均予測獲得点 `sum / visits` の降順、同点なら訪問数、さらに同点なら元のindexで上位2点を選ぶ。予測非GOは実ゲームでの安全保証ではない。
4. 上位の各点へ、隣接アンカーとの中間位置を1点ずつ提案する。間隔の広い側を優先し、同幅では探索seedと親indexから決定する。重複を避け、合計最大2点。条件を満たす親が1点だけなら、そのもう一方の隣接区間も利用できる。
5. 元5点とその統計・chance子・状態キャッシュをそのまま残し、新しいEdgeだけ訪問0で追加。残り96回を通常UCTで探索する。総数は128回で、32回を別途上乗せしていない。
6. 新候補も通常の未訪問選択・UCT・逆伝播を使う。最終選択も従来の即時GO除外・最大訪問数・平均評価による規則を維持する。

基本は5→7候補だが、親や重複の条件によって5または6のままの場合もある。全GOなら追加しないため、元5点が全てGO予測でも中間点なら安全という機会を、この方式が救えるとは限らない。

候補選別のための追加物理プローブは0。選別処理そのものの時間は単独計測しておらず、総判断時間に含む。32回・4訪問・上位2点という値は試作の事前設定であり、最適値ではない。

**未来のdecisionとrolloutは固定5候補のまま。** 実ゲームの次手で再びrootを細分化できることと、今回の探索中に細かな2手系列を調べられることは別である。深さ・UCT・chance分布・reward・rollout・物理・GOは変更していない。公開保持果物とNEXTを使い、実ゲームの未公開系列を探索側へ渡していない。

このモードは今回の固定128・深さ4・grid5・chance・random条件を対象とする実験で、既存adaptive・time・wideningとの併用を検証したものではない。既存のそれらの機能は残している。

## 採否と次の開発

今回は候補生成の機能と対応比較基盤は動いたが、高得点化・生存・2個目生成の改善を達成したとは報告しない。**基準MCTSを維持し、改良版は比較用オプションに留める。** 6ペアだけで一般的な弱さを証明したわけでもない。

次に32という閾値や候補数を同じ6ペアで調整して勝つまで繰り返すことは勧めない。まず生成前盤面も含め、複数候補の初手だけを変え、その後は同じ基準MCTSで続行する少数の実験に進むのが有益。今回の全方針比較とは分けて、落下位置そのものの差と後続方針の差を区別し、大きな果物を育てる行動の教師を集める。近似originを明記し、最適行動の真値とは呼ばない。新しい独立rootで確認する前に、今回の結果だけで学習モデルや候補追加を標準化しない。

主なデータ：`analysis_final.json`・`analysis_final.csv`・`final_audit.json`・`future_information_audit.json`・`go_board_summary.json`・`budget_close.json`・各試行の`trace.jsonl`。実験中にAIの設定・ソースは変更していない。途中で追加した解析項目はGO直前観測と未実施の明示など集計のみで、AIの判断には使っていない。
