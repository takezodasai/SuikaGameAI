## 2. 新しい探索配分

`RootBudgetAllocation` と `StagedRootMctsPlanner` を新規追加。旧MctsPlannerは変更していない。

1. 最初の40反復はrootの適格候補を最少訪問順で探索。全5候補が適格なら各8反復。
2. 40反復時点の平均評価で上位3候補を固定。平均同点は訪問数、index順。
3. 残り88反復を3候補へ均等に追加配分する。全候補適格なら29/29/30反復。
4. 最終的にshortlistの平均評価最大を選ぶ。同点は訪問数。全候補即時GO等の例外は従来fallbackを使用。

既知の落下失敗・即時GO候補は適格候補があるとき配分から除外する。未評価候補は最初に評価できる。40/3という値は事前固定の試作品であり、最適値ではない。

従来root UCTは各反復で平均値と探索項によって全候補を再比較する。新方式は40回で候補を絞り、以後は固定shortlistへ均等追加するため同じ処理ではない。非rootは従来UCT。最終選択も従来の訪問数中心から平均値中心へ変えており、今回の結果で配分だけの効果を分離はできない。

木・統計は128反復内で保持。追加の候補選別用物理probeは実行しない。

## 9. 20時間収集の推奨

今回ただちに安全に実行できるのは、既存 `collect_overnight_mcts.py` と `SyncOptimized_03` による従来固定5候補MCTS。新方式は収集の標準にしない。

前回保存済み収集では利用可能124ゲームのうち深さ4/128が60件、深さ4/256が35件、深さ4/512が15件、深さ6/256が14件。異なるseedなので方式間の得点優劣は推定しない。深さ4/256の実行時間平均は約1,310秒だった。今夜は深さ4/256に統一し、同一続行方針の価値教師を増やす。これで未選択行動の教師が得られるわけではなく、分岐教師は別途必要。

2並列・最大30秒/判断・通信720秒・新規投入20時間・drainを推奨。以前の実行時間が維持されれば数十〜100ゲーム前後が目安だが、同時負荷・盤面・Player性能に依存し保証しない。20時間後は新規投入を止め、実行中ゲームは保存まで継続するため総終了時刻は20時間を超えうる。厳密な20時間停止を選ぶ場合はboundaryだが、未完ゲームを自然GO教師には使わない。

新しい収集seed範囲913400000〜913400999は保存済みcollection設定および予約Test19 seedとの重複なしを確認。ただし初期果物系列の一致は後からグループ化して分割漏洩を防ぐ必要がある。

同じ端末で再開する場合は `--output $out --resume`。新しいtagで同じseed範囲の収集を重複起動しない。既存モデルやTestへ自動追加・学習はしない。
