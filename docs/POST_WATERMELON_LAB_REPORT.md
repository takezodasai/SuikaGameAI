# スイカ生成後の実ゲーム続行環境：実装・動作結果

2026-10-31。今回は計画だけでなく、スイカを含む盤面を独立Playerへ読み込み、既存MCTSが実際に落下操作を続ける環境を実装・実行した。

## 完了したこと

- Training用の独立3seed群から、生成直前・生成直後・生成後の危険局面を各1件、計9盤面を抽出した。予約Test19のseed・初期8果物系列を除外した。
- **近似再構成盤面**から既存の同期MCTS128回・深さ4・固定5候補・random rollout・post25tickで続行できる専用モードを実装した。元ゲームの厳密なcheckpoint復元ではない。
- 基準の1試行は自然GOまで完了。スイカ1個を含む2,229点の盤面から、追加278点、最終2,507点、39落下した。
- 初手だけ変更する試行、別盤面の続行、GUIでの3落下を実行した。途中打ち切りは自然GOとは別扱い。
- 追加得点・落下数・新しいスイカ生成・2個共存・ダブル達成・実イベント・状態・RNG・相対tick・計算時間を記録する。2個目やダブルの実達成例は今回得られていない。

## 実装の性質

`-suikaWatermelonLab <config.json>`でのみ起動する。通常のPlayer起動・MCTS・既存モードには追加しない。

1. 既存の診断用`LoadFixture`で現在のPrefabから盤面を作る。ルール、Collider、重力、GOライン、生成確率は変更しない。
2. オブジェクトのStart・Collider初期化後に、保存済み位置・回転・速度・角速度・判明しているsleep値を再適用する。保持果物の高さも既知の場合は適用する。
3. 元の接触cache・sleep内部タイマー・merge進行中の内部状態・元のRNGや絶対時間は復元できない。明示した新しいfuture_seedで実験用未来を開始する。
4. MCTSへ渡すのは既存の盤面と公開保持/NEXTだけ。future_seedは実ゲームの生成側に設定し、探索設定へは渡さない。探索seed8191は別に固定する。計画の前後で実盤面署名とUnity乱数状態が変化していないことを検査する。
5. 通常の移動・cooldown・`TryDropAt`・物理更新を使って実際に落とし、落下後25tickで次の判断へ進む。探索中は実世界の時間を止める。

3盤面の読み込み直後は、比較した果物の種類・位置・速度・回転・接触済みフラグ、得点、保持/NEXT、保持座標、cooldownが保存値と一致した。**公開値の一致は、内部物理状態の一致を意味しない。** 元ゲームの絶対tick・時計を移植したとは扱わない。詳細は`final_integrity.json`。

初手のみ`--first-x 0.25`や`0.37`で変更できる。以後はMCTSが判断する。これは比較のための強制初手で、正しい戦略として教えるものではなく、学習報酬にも使わない。

## 実イベントの計測

既存`SuikaEpisodeEvents`の実ゲームcallbackを観測する。予測Sceneのcallbackは含めない。

- 持込スイカ数をbaselineとして別保存する。Reset後の既存イベント記録は0から始まるため、その`watermelons_present`や`second_watermelon`ラベルを無補正で信用しない。
- 新規生成数をcreated、ダブル回数をdoublesとし、実験内の存在数を `initial_watermelons + created - 2*doubles` で追跡する。callbackを順番に処理し、同じtick内の短い共存も数えられるようにする。
- 持込1個に対して新規生成が1回あれば、実験内の「2個目生成」とする。元ゲーム全体で何個目だったかを再現するラベルではない。
- 最終03では新規生成・ダブルの変化を物理更新後の`milestone_post_physics`として盤面付きで記録する。callbackその瞬間の全native状態の保存ではない。イベントの発生位置・得点・drop_count等はraw_eventsにも残る。
- 今回の試行には新規生成・ダブルの正例がない。新しいbaseline補正を含む全経路が実達成例で検証済みとは報告しない。

`natural_go`、`truncated`、`exact_historical_replay=false`を別々に保存する。自然GOした場合のreturnは「近似実験盤面からの、その後の方針による実現return」であり、元の歴史ゲームからの真の反実仮想returnではない。

## Player・GUI・停止

現在使用するのは `Unity/Builds/WatermelonLab_03/SuikaGameAI.exe`。01は初期復元例外が出た版、02は自然GO試験を含む動作版で、すべて別フォルダに残した。

01では旧ヘルパーが保持プレビューにもRigidbodyがあると仮定した箇所で例外となり、0操作・プロセスタイムアウトで終了した。ログを保持し、成功件数に含めない。新モード内の復元では保持Rigidbodyがない場合にも対応し、通常の解放処理のまま扱う。旧ヘルパーは変更していない。

02→03は、開始得点のUI再表示と新規milestone観測を追加した。03はルール・MCTS・経路テストとGUI3落下を実行し、02の同じGUI3落下との比較公開値が一致した。**03で自然GO全体を再実行したわけではない。** 自然GOの実測は02の115秒試行である。

画面には近似モードの表示、現在得点・追加得点・落下数・MCTS設定・判断時間を表示する。Escapeで上限終了と区別して停止する。Ctrl+Cやウィンドウ閉鎖でも、Pythonは既存行を残して不完全結果として保存する。同期の計画中は画面・Escape処理が停止し得る。時間上限も計画呼び出しの途中では割り込まない。今回の1判断は約2秒だったが、他の重い条件で同じ上限超過とは限らない。

GUIを実表示して3落下を完了した。新規Player初回にWindowsの通信許可ダイアログも表示されたが、こちらで許可操作やFirewall設定変更はしていない。3落下は正常完了した。スクリーンショット`gui_final_screenshot.png`ではそのダイアログが一部を覆っている。画面確認APIが起動不能だったため、所有Playerのウィンドウを確認してネイティブのスクリーンキャプチャを使用した。

## 実行コマンド

まず3落下だけ表示する場合：

```powershell
Set-Location C:\SuikaGameAI\Python
$tag = (Get-Date -Format 'yyyyMMdd_HHmmss') + '_' + [guid]::NewGuid().ToString('N').Substring(0,8)
$out = "outputs\watermelon_gui_$tag"
.\.venv\Scripts\python.exe .\watermelon_lab.py play `
    --exe ..\Unity\Builds\WatermelonLab_03\SuikaGameAI.exe `
    --fixture .\outputs\watermelon_lab_01\source_0\after.json `
    --output $out --iterations 128 --future-seed 2026103103 `
    --drops 3 --seconds 30 --port 42880 --gui
```

より長く続ける場合は、同じコマンドで新しい`$out`を作り、`--drops 1000 --seconds 600`へ変更する。自然GOなら自然GOとして、先に上限へ達したら打ち切りとして保存する。自然GOまでの到達を保証する上限ではない。別盤面は`source_1/after.json`または`source_2/after.json`へ変更する。最初の行動だけを比較する場合は`--first-x 0.25`等を追加し、以後のMCTSは同じままにする。任意座標を入力できても、その座標が有利とは限らない。既存ポート使用を検出した場合は重複起動せず停止する。

## 残る課題と次の使い方

厳密な歴史再生と、2個目・ダブルの正例によるイベント検証は未達成。今回は近似実験環境が動くという完了条件を満たしたので、再生調査だけへ戻らない。

次はこの3つの近似rootを固定し、複数の新しい共通未来seedで基準MCTSの続行を測る。最初は小規模に、生存・追加得点・大きな果物の成長・GO状態を記録する。その中からMCTSと別候補の提案が分かれる局面だけ、少数の初手変更を試す。見えている開始状態の一致と繰り返し時の結果のばらつきも一緒に報告し、最適行動の正解教師とは呼ばない。将来の学習に使う場合も`approximate_origin`を保ち、実ゲームの歴史的な正確分岐とは別データセットにする。特定位置への報酬・新しいモデル・MCTSの標準変更は今回導入していない。
