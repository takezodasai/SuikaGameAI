## 結論

**候補比較の基盤は実装・動作確認できたが、現在の価値モデルが実ゲームでより有利な落下位置を選べると判断するには不十分。MCTSへ標準接続しない。**

保存済みの位置・速度・回転は診断用復元処理の修正後に6盤面すべてで一致した。しかし元のnative接触履歴・sleep内部タイマー・元RNG状態は復元できない。接触盤面では再構成した実ゲームと予測Sceneの数値差が最初の物理tickから発生した。短い窓の得点が一致しても長期の反実仮想の正解とはしない。

既存価値モデルは6落下までの予測Scene続行で良い候補を選ぶ例があった一方、候補ペアの順位一致は55.8%で、単純heuristicの61.6%を上回らない。選択した候補の短期得点差では別の傾向もあり、一つの指標で採用を決められない。6落下のreturnとGOまでの価値は期間が異なるため、この順位診断だけで長期価値を否定することもできない。

元の実ログのGO直前状態でも、モデルは約134.9点、実際のその後の獲得は10点だった。これは予測Sceneによらない観察だが、1ゲームの1局面であり一般的な過大評価率の推定ではない。

## 2. 復元の正確性と限界

### 検出・修正した問題

既存fixture loaderで、Rigidbodyの速度を設定した後にCollider／Start初期化が進むと、保存速度が変化する例を検出。初期診断では最大の成分差が約0.216 world unit/秒あった。今回の**新しい診断コンポーネントだけ**で、初期化待ち・Transform同期後に保存位置／回転／速度／角速度を再適用した。既存loader、MCTSのコピー処理、実ゲームの物理設定は変更しない。

修正後、元fixtureと再構成した実ゲームの初期状態の `x,y,vx,vy,angle,angular_velocity` の最大差は全6盤面で0。型と配置による対応付けが不明確な場合はエラーにする。これは保存された可視フィールドについての結果である。

### 完全復元できない情報

Job7のdecision_sourceには保持Y、残りcooldown、元のgame tick、RNG状態等がない。診断ではcooldown=0、保持Y=現在のspawn高さという仮定を**明示して**再構成した。これを元の盤面と正確に一致した状態とは呼ばない。過去の接触・sleep情報もknown=falseのものは未知のままであり、再構成後に測れた値を過去の実測値へ上書きしない。

`prepare_candidate_fixtures.py` は欠損可視フィールドがあると原則拒否し、`--allow-cold` を指定した場合だけ仮定を別欄に記録する。元ログのpost_stateには保持Y・cooldown・tickが保存されており、3状態の厳格な可視状態exportにも成功した。ただしpost_stateにもsolver cache等はなく、native checkpointではない。

新しい診断記録では、実ゲームの可視状態、物理属性のknown flag、診断game/fixed clock、Unity RNGのs0〜s3を保存するAPIを用意した。RNGはモデル入力ではない。通常の収集へ自動挿入するhookや、native内部状態を完全保存する仕組みは今回実装していない。次の収集で判断境界の観測用capsuleとして接続できるが、現在の収集Playerは差し替えない。

## 7. 次期学習データの設計

今回 `branch_targets_simulator_only.jsonl` に108例を出力。21例は予測SceneでGOまで到達、87例は打切り。これはすべて `actual_game_teacher=false` の診断資料で、元の自然GO教師へ混ぜていない。将来の追加点をモデル入力へ混入しない。打切り例の完全returnはnull。

今後のrecordは次を分離する。

- `input`：評価時点の盤面、保持／公開NEXT、得点、cooldown、既存known flag。
- `action`：合法範囲、正規化X、実座標、移動／落下／窓終了tick。
- `provenance`：元game/seed/group、Player・モデル・環境hash、source phase、復元仮定、公開情報の範囲。
- `target`：実測か予測か、同一続行方針、未来サンプルID、prefix return、終端／打切り、完全returnのknown mask。
- `bootstrap`：n-stepへ進む場合の終端側状態。これは現在状態のモデル入力とは別欄。
- `events`：actual_gameとpredictionを分離し、個々のDrop/Mergeのstep／物理時刻を記録。今回の文字列traceのframe番号を無条件に実物理tickと同一視しない。

branch、反復、未来サンプル、生成前後の状態は、元のseedグループの分割を継承する。Job7は既存policy Trainに使われており、今後独立Testへ移さない。既存Testは再学習・閾値調整へ使わない。

次に学習するなら、モデルを大きくする前に**同じ既存構造で、実MC returnの校正と、同一盤面内の行動順位を併用する学習**を対照実験する。ただし短いprefixを長期returnの正解にしない。まず実測MC教師を維持し、少数の共通方針・複数未来による終端継続を追加して行動順位教師の信頼性を確かめる。スイカ補助教師はactual callbackのknown maskを使う。
