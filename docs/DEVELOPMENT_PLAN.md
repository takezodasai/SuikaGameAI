# 開発計画

過去資料の復元ではなく、ユーザー提示の計画を記録する。

0. 既存ゲームの分析・動作確認（初回確認済み）
1. 既存ゲームの不具合修正（通信停止エラーはユーザーがUnity確認済み。残りは保留）
2. 数値によるゲーム状態取得・Reset（実装・短時間の実通信確認済み）
3. X座標指定による果物の落下（実装・端点/5種類/重複送信/連続stepの実通信確認済み）
4. 物理シミュレーターの構築（完全一致は要求しない。GO診断・報酬区間・実効速度を整備し、短時間の回帰検証を経てSTEP 5の設計へ）
5. 簡易評価関数による1手先探索
6. 複数ゲームの並列実行
7. Value Networkの学習
8. MCTSによる先読み探索
9. 複数画面表示・YouTube撮影機能

STEP 3.5：STEP 3の移動を固定物理更新による一定速度移動へ変更。Inspector速度調整、移動中reset、盤面物理の継続を実通信確認済み。STEP 4は実験用実装と実測比較まで実施。2026-10-21のユーザー方針で完全一致を必須条件としない。主要問題の改善と短時間検証後にSTEP 5を設計する。実装は設計案へのユーザー確認後。

最終目標は高得点AI。学習時は描画を省略し、必要時だけ複数プレイ画面を表示する。モデルと学習進捗を保存し、再起動後に再開可能にする。今回は新しいAI実装には進まない。

STEP 1の次回候補（未修正）：Time.timeScaleの競合、gameOverText未設定、InspectorのMissing参照、初期化順序、果物タグ不一致。Missing・タグ問題の範囲と再現条件は未確認。


## 2026-10-21の合意と長期目標
- 当面は1種類の高得点AIに集中する。STEP 5は簡易評価関数と1手先探索、STEP 6は複数ゲーム、STEP 7はValue Network、STEP 8はMCTS、STEP 9は表示/撮影。順序を維持する。
- 将来は不確実な未来の果物を完全に知ることなく、10/20/30手以上先の利益・大きな連鎖を合理的に考えるAIを目指す。全パターンの力任せ探索は前提にしない。
- 将来的な高得点/速度/長期戦略/連鎖/ダブルスイカ/合理的な意外性などのAIモードを想定する。係数だけでなく判断方法・探索・思考予算を交換可能にするが、現段階で各モードは設計/実装しない。
- 状態取得・物理予測・操作とAI判断を分け、既存基盤を再利用する。STEP 5の具体案はSTEP5_DESIGN.md。現在は設計案のみで、承認前にSTEP 5を実装しない。STEP 6以降も開始しない。
- 学習時の描画省略、必要時のみ表示、モデル/進捗の永続化と再起動後の再開という目標を維持する。今回これらの高速学習機能は追加しない。
