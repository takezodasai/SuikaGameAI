# MC・3-step TD・混合価値学習の統一条件比較

## 結論

今回のモデル・データ・学習予算では、純TDはMCより悪かった。MC＋TDはMCとほぼ同程度で、標準採用できる一貫した改善はない。MCを基準として維持する。

混合方針データでのValidation MAE（3学習seed平均±標準偏差）は、MC347.7±4.7点、TD491.9±23.0点、TD25%混合347.1±6.0点、TD50%混合347.9±11.2点。事前指定したseed群・ゲーム均等MC MSEではMCが最良だった。

独立Test評価、実ゲーム得点比較、MCTS統合はしていない。既存Test5ゲームは方式選択・推論に使わず、新しい学習用テンソルからも除外した。新規未使用Testの確保は今回は行わず、Validation結果だけを報告する。

出力：`Python/outputs/mc_td_compare_01`。新規24モデルとcheckpointは全てその配下。既存モデル・データ・Player・Unityソースは変更していない。

## 1. 比較条件

学習前に `experiment_plan.json` を保存。主比較と補助比較それぞれで、以下を統一した。

| 入力 | fruit30、global37、geometry57、既存特徴量・欠損フラグ |
| 出力 | 当該観測からの将来追加得点、非負Softplus、既知GOは既存maskで0 |
| 点数単位 | 1000点を学習上1として正規化、報告は実得点単位 |
| optimizer | AdamW、lr=.001、weight_decay=.0001 |
| scheduler | StepLR、8epochごとにlr×.5 |
| 学習率 | epoch1〜8=.001、9〜15=.0005 |
| 上限 / early stopping | 最大15epoch、patience4 |

| 補助損失 | 別盤面間ranking補助・成功例重み・GO直前重みは全方式でOFF |
| checkpoint選択 | Validationでseed群→ゲーム→状態を均等化したMC MSE最小 |

旧AC checkpointそのものの再現実験ではない。以前のranking補助lossを全方式で無効にし、return教師の学習法だけを比較した。

同じ学習seedでは、初期parameterのhash、共通epochの抽出順hash、NEXTマスクhashが4方式で一致した。学習seedは初期化だけでなく抽出・マスクの乱数も変える。seedが違う3学習を、追加の独立ゲームとして数えない。

early stopping条件は同じでも停止epochは異なる。純TDにはMC事前学習を行っていない。全て同じランダム初期値から開始した。

### 学習式

MC教師：`G_t = S_final - S_t`。

3-step TD教師：`Y_t = (S_{t+3}-S_t) + 1[実測非終端] V_target(s_{t+3})`。

終端が3観測より前なら実測終端で打ち切り、bootstrap=0。gamma=1。rewardを3で平均したり、MCTSの55点scaleを混ぜたりしていない。

- MC：`L = MSE(V,G)`
- TD：`L = MSE(V,Y)`
- 混合：`L = (1-λ)MSE(V,G) + λ MSE(V,Y)`、λは事前指定の.25/.50だけ。

target networkは各epoch開始時にonline networkをhard copyし、そのepoch中は完全に固定する。教師はdetachされ、targetへgradientを流さない。終端のnetwork入力自体を作る必要はなく、実測GOなら0とする。Targetも同形の別コピーで、推論モデルのparameter数は増えない。

bootstrapに未来状態を使うことは教師生成であり、現在盤面の入力に未来情報を加えることとは異なる。3観測先の盤面は同じTrain episode内に限定。Validation/Testの状態をTrainのbootstrapへ使わない。

### 方針差とデータ量を混同しない

混合データで学習したモデルも、同じ固定設定のValidation5群に限定して評価した。

| 学習データ | MC MAE | TD MAE | 混合25% MAE | 混合50% MAE |
|---|---:|---:|---:|---:|
|混合方針Train132|373.5|392.4|361.7|351.5|
|固定設定Train20|246.4|425.5|246.0|255.0|

評価側の5群をそろえても挙動に差がある。ただし、学習ゲーム数・状態分布に加え、checkpointを選んだValidation集合も19群対5群と違う。方針混在だけを原因とする対照実験ではない。

混合設定のreturnは、その後の探索予算・候補方式・打ち切り上限等の行動方針に依存する。現在のネットワークには方針IDを入力していないため、同じ公開状態からのreturnを複数方針で平均する傾向を学び得る。これは不正な教師ではないが、ある特定の続行方針の価値や、最適可能得点と同じではない。

限定データではTrain MAEがMC360.2、TD508.9、混合25%357.5で、Validationより高かった。Train/Validationの難易度・return分布が違い、gapの符号だけを過学習指標として解釈しない。

## 5. 学習予算と限界

選択epoch：主比較MC5/3/2、TD15/15/15、混合25%5/3/4、混合50%5/5/4。純TDは上限でもValidationが改善中のrunがあり、収束したと保証できない。

targetをepochごとに更新するscratch TDでは、長期returnの伝播に時間がかかる可能性がある。今回の失敗をTD一般の不可能性とは扱わない。一方、成功させるためにepochやtarget更新を後から変更して再比較することもしなかった。

全24試行の学習・checkpoint・評価時間合計約782秒（約13分、特徴量準備等を除く）。CPU1thread。主比較3seed合計はMC114秒、TD272秒、混合25%145秒、混合50%157秒。TDは追加forwardに加え、早期停止せず長く学習した分のコストもある。

TDの正当性確認には、終端bootstrap・正規化・detach・Validation bootstrap拒否・境界拒否等のテストを追加。Python394テスト成功。Unity・Player・MCTSを変更していないため、ビルドやゲーム実行はしていない。

## 6. 採否と次の方針

**MCを基準として維持する。純TDと混合を標準採用しない。**

混合25%には一部局面や限定データで小さな改善があるが、主比較の事前選択指標でMCを上回らず、学習seed間の差も考慮すると十分な根拠ではない。GO直前や高得点帯の改善も一貫しない。

これ以上、TDのhyperparameter調整だけを続けるより、次を優先する：

1. 続行方針と観測phaseを明確にしたMC教師を基準にする。
2. 同一rootの実ゲームで複数候補・複数の共通未来・固定した続行方針を比較し、自然GOまでの候補順位教師を少数から作る。
3. fresh-process再生の全prefix検証に不合格な局面は教師化しない。自然GOと短期打ち切りを混ぜない。
4. その独立した候補比較で、valueが有利な行動を選ぶ能力を評価する。MAEだけでMCTSへ接続しない。

現在の4落下分岐データは自然GOの正解ではないため、今回の学習・選択には使わなかった。将来の全分岐・未来系列・再実行は親rootのseed群と同じsplitにまとめる。新たな未使用Test群を確保する際は、方式・設定・評価規則を固定して一度だけ評価する。

MCで学習する価値も最適価値ではなく、観測された方針下の期待returnを推定するもの。実際の高得点化は未検証であり、モデル構造の大型化が必要だとも結論していない。
