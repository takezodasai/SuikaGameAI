# STEP 7-C 50組比較：集計エラー調査と結果（2026-10-22）

入力: Python/outputs/value_compare_50_20261022_164130。100ゲームの再実行なし。原本ログ・モデル・ゲーム本体の変更なし。出力は別フォルダ value_compare_50_20261022_164130_analysis_01 へ新規保存。

## 直接原因

SuikaPhysicsSimulator.Result.applied_xはfloat初期値0（28行）。実際に予測落下したときだけRunの348行で代入される。GOの場合は378行でループ終了するため、落下前GOではdrop_success=false/drop_tick=-1/applied_x=0。この0は中央へ落下した予測ではなく、落下位置が未定義という意味。旧summarizeは実ゲーム側のdrop_successだけを条件にし、この未定義値を実際の落下座標と比較していた。

該当18件（heuristic5/value13、14episode）はすべて全候補GOの既存fallbackで選択された候補。予測は落下前GO、実ゲームは指定位置まで移動して落下した。11件は実step完了時非GO、7件は実step完了時GO。浮動小数点誤差や通信による別候補へのすり替わりではない。実ゲームと予測のGO発生タイミング不一致は実際に残っているが、それを操作座標不一致と誤判定した。

実装の対応箇所: UDPStepProtocol.FixedUpdateはtarget到達後TryDropAt（187行）を呼び、最終DropRangeとapplied_xを保存する（189行以降）。PlayerDropPlacement.TryDropAtは実Collider由来の範囲からLerpし、安全検査後に落下する。移動中の範囲変化チェックは1e-5（UDPStepProtocol165行）。実ログの実際落下/当初targetと、両側落下済みの予測/実落下の最大微差はいずれも9.775161743e-6 world unitsで既存許容範囲内。範囲外の座標や異なる命令はなかった。

## 修正と検査

compare_value_ai.validate_selected_actionを追加。両側drop_success=trueのときだけ予測applied_xと実applied_xを比較する。予測未落下のapplied_xは解析上nullにし、元の0も診断用に保存。閾値は1e-5のまま広げない。選択index/正規化X/命令X/目標X/最終範囲からの座標/実落下X/範囲内/GO候補除外・allGO fallback条件を別々に確認する。真の不一致はaction_errorsへ記録し、該当ペアを平均・勝敗・CIから除外する。全ログを走査し最初のエラーで集計を止めない。

--report-dirで原本と別フォルダへ保存。既存ファイルはexclusive createで上書き拒否。回帰テストは予測落下前GO、実GOで未落下、真の座標不一致、別命令、GO除外、NaN、既存結果保護、異常ペア除外など。ゲーム本体コードは修正していない。最終確認は回帰13件を含むPython全111テスト成功。
