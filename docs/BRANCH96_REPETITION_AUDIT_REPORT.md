## 5. MCTS最終候補の決定とA/B/C/D

`MctsPlanner.cs:398` でroot平均をsearch_scoreへ設定。deep terminal率は診断のみでsearch_terminal_probability=0。StepPlanner.Chooseで通常/全GO fallbackを処理した後、`MctsPlanner.cs:404` 以降で通常候補について最終的に:

1. success/drop_success、即時非GOの候補を対象。
2. 訪問数最大。
3. 訪問数同数なら平均が0.001超高い候補。
4. それでも同じなら元の候補順。

全GO時の生存fallbackはそのまま。今回のrootでは全GOではない。

## 9. 次の実際のAI改良

優先はA側、ただし標準MCTSを即変更するのではなく、単純な候補選択の独立検証。

1. 新しい独立元seed群で、事前固定のA対Bを少数比較。今回の6rootで閾値・B選択規則を最適化しない。Bは「A以外の平均最大」という既存規則のまま比較基準に残す。
2. まず条件付き初手比較を確認し、有望なら別モードで通常開始→自然GOの対応比較へ進む。初手だけの改善を毎手Bを選ぶAIの強さとみなさない。続行方針が変わるため別の検証が必要。
3. C/Dは今回同じで識別不能。新rootでC/Dが異なった場合だけ、実行した座標のreturnに基づき比較する。
4. 盤面によってA/Bの有利さが変わり、その違いを未使用rootへ予測できるデータが増えたら、小型差分Qへ進む。必ず「常にA」「常にB」を基準にする。6rootを使って大きな学習・パラメータ調整はしない。
5. 未来の追加は不確実性を減らすため、独立root追加は汎化を見るため。4反復の再度収集は最優先ではない。意図的反復は時相差の診断など目的を明示した少数に留める。

今回のデータは信頼性を明示した開発教師として利用できるが、ダブル成功例は0。成功率改善を証明したものではない。次も自然GO得点と生存・新規スイカを主指標とし、人間の特定配置攻略や追加報酬を導入しない。
